Automation architecture

Test framework structure, layer boundaries, maintainability, and reliable quality signals.

Questions and practice

Open a question to see the answer, examples, and exercises.

What should be automated first?

Answer

Stable, repeatable, high-risk scenarios with a reliable oracle and acceptable maintenance cost.

Examples

  • A critical checkout with a clear API outcome is usually a better candidate than a changing visual prototype.

Practice exercises

  1. Compare two scenarios by risk, repeatability, oracle quality, and maintenance cost.
What is a flaky test?

Answer

A test with unstable outcomes under materially identical conditions; the cause may be in the test, environment, or product.

Examples

  • A test sometimes fails because of a request race even though code and test data did not change.

Practice exercises

  1. For an unstable test, plan the evidence to collect before adding a retry.
Why separate test logic from client and page layers?

Answer

So scenarios describe behaviour while protocol and UI details change locally.

Examples

  • An API endpoint change should require updating the client, not every business scenario.

Practice exercises

  1. Design a checkout flow—API setup, UI action, API assertion, cleanup—and mark the layer boundaries.
