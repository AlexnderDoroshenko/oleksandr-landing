AI System Testing

A bilingual learning path across 12 topics, from test process and Python to RAG, MCP, agents, evaluation, security, and Responsible AI.

Reviewed: 2026-10-06

Testing is the static and dynamic examination of a product and related work products to identify defects and determine alignment with requirements and user needs. This is a teaching definition, not a verbatim standards quotation.

Check deterministic properties with code assertions and semantic quality with a defined rubric, calibrated evaluation, and human review. Diagnose model, retrieval, application, tool, and environment failures separately.

Work through one topic at a time: answer from memory, read the explanation, complete the exercise, and preserve evidence. Numeric thresholds and sample sizes are illustrative rather than normative.

Learning project

Use a read-only AI Quality Architect over fictitious Jira/Confluence fixtures. It analyses requirements and coverage and creates a cited strategy report. Add write tools only after separate permission and approval validation so datasets, retrieval, reasoning, and execution can be evaluated independently.

Completion criteria

Junior
Create 10 cases with inputs, contexts, expected properties, and forbidden actions; implement schema and exact-ID checks.
Middle
Add retrieval metrics, mocked tool failures, a two-turn conversation, and paired prompt comparisons. Preserve versioned traces and sanitized evidence.
Senior
Justify dataset coverage, judge calibration, release gates, residual risks, cost, and privacy. Demonstrate recovery and rollback and explain which claims the evidence does not establish.

Topic completion means an explanation in your own words, a runnable example, a verified negative case, a report with denominators, versions and evidence, explained limitations, and equivalent Ukrainian/English content. A high quiz score alone does not establish Senior competence.

01 / 12

Documentation and testing process

Practice

Write a requirement-gap test case for AI Quality Architect. Include versioned input, acceptable findings, prohibited claims and evidence. File a defect for a fabricated risk and justify severity and priority.

02 / 12

Python for automation

Practice

Write a typed evaluator that reads JSONL, yields results lazily and closes the file even after an exception. Add pytest cases for nested copies, invalid input and a custom exception.

03 / 12

AI and ML fundamentals

Practice

For a documentation assistant define the context budget, data access, hosting choice and guardrails. Explain how to test loss of an early instruction in a long conversation.

04 / 12

Prompting and tool calling

Practice

Create a JSON report prompt with source IDs. Test missing context, conflicting instructions and a malicious tool result; use validators rather than polished reasoning to judge correctness.

05 / 12

RAG and retrieval

Practice

Prepare 10 queries, relevance labels and document versions. Calculate precision@3 and recall@3 manually, then inspect citations for an answer using contradictory documents.

06 / 12

Agents and coordination

Practice

Design an API → browser → API checkout run. Define allowed tools, budgets, handoffs, stop conditions and human approval for actions with side effects.

07 / 12

MCP and contract testing

Practice

For a read_order tool test valid calls, missing required IDs, invalid types, unauthorized orders, application errors and timeouts. Pin the protocol version and a separate business contract.

08 / 12

Frameworks for chains and graphs

Practice

Implement a mock template → retriever → model → validator pipeline. Add a retrieval checkpoint and verify that resume does not repeat a side effect.

09 / 12

GenAI test automation

Practice

Create a paired comparison of two prompt versions on 20 cases. Preserve raw scores, critical failures, cost and repeats; do not let an average score hide unsafe actions in the gate.

10 / 12

Evaluation and golden datasets

Practice

Create a golden set of 12 assistant conversations covering happy paths, no answers, ACLs, clarification, stale data and malicious contexts. Label acceptable outcomes, forbidden actions and each turn.

11 / 12

GenAI security and privacy

Practice

Threat-model a RAG assistant with tenants, private documents, external models and tools. Put canary secrets only in synthetic fixtures and verify no output or log leakage.

12 / 12

Responsible AI

Practice

For a bilingual assistant choose a fairness criterion and Ukrainian/English slices. Evaluate false refusals and task success, explain sample limitations and assign residual-risk owners.
